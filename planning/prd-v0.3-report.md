## 3. Inconsistencies found, not fixed (pre-existing or out of scope)

1. **FR-74 vs §8.5.** FR-74 allows a service override to `close` "from any state" while §8.5 only has `issued → closed` (and now `in_revision`). A close without issuance is functionally a cancellation; the PRD does not say whether the record of such a service should show "closed" or "cancelled".
2. **FR-30 blocking types vs §8.5.** FR-30 says open CARs block "manager approval"; §8.5 does not show where the block sits (`draft → independent_review` or `manager_review → approved`). v0.3 only moved the type list into the template key `blocking_finding_types`.
3. **User story numbering.** Stories 25–33 were appended by section (client 25–27 after 10, verifier 28–33 after 17) so existing numbers stay. Reading order is no longer numeric; a future clean-up could reorder without renumbering by using sub-headings.
4. **`approvals.kind` has no `materiality` kind.** Materiality is approved through the existing `audit_plan` approval (D18). If the audit plan and materiality ever need separate approvers, a kind must be added.
5. **§9.3 `services.team_leader_user_id` is denormalised** from `service_team`; with the involved set now derived from `service_team`, the column is informational only. Not changed.
6. **§8.5 "Record" machine has no explicit `superseded → withdrawn`.** A withdrawn statement that was itself already superseded does not affect records (they point to the replacement). Worth a sentence in a later revision.
7. **Paid status visible to the decision-maker** (out of scope per the brief §5); unchanged.
8. **`decarb_unit` methodology gaps** (double counting, chain of custody, permanence) remain as in v0.2 per the brief.
